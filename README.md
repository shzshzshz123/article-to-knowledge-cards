# make-knowledge-cards

把**粘贴的文章**或**本地 Markdown / TXT 文件**转换成**一组知识卡片**的 Agent Skill。

## 项目解决什么问题

长文章读完就忘，是因为信息密度低、重点被淹没在叙述里。市面上的摘要工具又常犯两个毛病：
**什么都留**（等于没提炼）和**无中生有**（用模型自己的知识补充原文没有的内容）。

本项目提供一个可复用的 Skill，把一篇文章压缩成一组**可复习、可自测**的知识卡片，并且：

- 只保留真正重要的知识点，不按比例平均分配篇幅；
- 一张卡片只讲一个知识点，不重复、不合并不同概念；
- **严格忠实于原文**——不编造原文没有的事实、数字、例子或推断；
- 原文信息不足时**如实减少卡片数量**，而不是硬凑到目标数；
- 卡片数量随源文长度伸缩，长文不会因为固定上限而被削掉重点。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 多来源读取 | 支持对话中粘贴的文章文本，以及本地 `.md` / `.markdown` / `.txt` / `.text` 文件 |
| 场景识别 | 先判断输入形态再动手：已是卡片/摘要的输入不再二次压缩；多篇文章分别成组；含代码、表格、公式的输入原样保留；超长文按原文标题分节处理 |
| 知识点提取 | 按重要性筛选结论、机制、定义、可执行规则、常见误区，忽略寒暄与营销话术 |
| 去重与合并 | 合并表述不同但含义相同的重复内容；同一知识点只出现一次 |
| 卡片生成 | 每张卡片包含标题、核心知识、简明解释、以及二选一的例子或自测问题 |
| 语言与标签一致 | 输出语言与原文一致（中文原文出中文卡片，英文原文出英文卡片），字段标签跟随输出语言；用户显式指定语言优先 |
| 数量自适应 | 按源文长度取目标区间（3–12 张），内容不足时如实减少并附一行说明 |
| 格式自检 | 内置 `check_cards.py`，对张数、字段完整性、一句话约束、标题规范、重复标题、语言一致性做硬校验 |
| 输入边界处理 | 遇到 URL、PDF、图片等不支持的输入时明确说明限制，并给出替代方案 |

### 知识卡片的结构

| 字段 | 说明 |
| --- | --- |
| 标题 | 一个具体、可检索的名词短语，点明该卡片的知识点 |
| 核心知识 | 一句话，只陈述一个事实、结论或规则 |
| 简明解释 | 2–4 句，说明原因、机制或影响 |
| 例子 或 自测问题 | 二选一，不可同时出现；概念类优先自测问题，方法类优先取自原文的例子，原文无例子则改用自测问题 |
| 原文依据（可选） | 用户要求可溯源时附加的原文短引用（≤40 字） |

## 安装方法

本 Skill 不依赖任何第三方包或运行时（校验脚本只用 Python 标准库），只需把技能目录放到
宿主的 skills 目录中。

```bash
# 方式一：个人级（对所有项目生效）
cp -r skills/make-knowledge-cards ~/.codebuddy/skills/

# 方式二：项目级（随项目共享，团队内所有人可用）
mkdir -p .codebuddy/skills && cp -r skills/make-knowledge-cards .codebuddy/skills/
```

Windows PowerShell：

```powershell
# 个人级
Copy-Item -Recurse skills\make-knowledge-cards "$HOME\.codebuddy\skills\"

# 项目级
New-Item -ItemType Directory -Force .codebuddy\skills | Out-Null
Copy-Item -Recurse skills\make-knowledge-cards .codebuddy\skills\
```

其他支持 Agent Skills 的宿主同理，放入其约定的 skills 目录即可（目录名必须保持
`make-knowledge-cards`）。`agents/openai.yaml` 是面向 OpenAI 系宿主的界面元数据（显示名、
简介、默认提示），宿主不识别时忽略即可。

## 使用方法

### 1. 触发技能

用自然语言提出请求即可，例如：

- `把这篇文章做成知识卡片：<粘贴文章内容>`
- `把 ./notes/xxx.md 整理成知识卡片`
- `把这段内容整理成闪卡 / 读书笔记`
- `把这段内容整理成知识卡片，用中文输出`
- `Make knowledge cards from this article.`

### 2. 提供输入

仅支持两种输入来源：

- 直接在对话中**粘贴文章文本**；
- 提供**本地文件路径**，扩展名为 `.md` / `.markdown` / `.txt` / `.text`。

### 3. 获取输出

Skill 会按「读取判断 → 提取知识点 → 去重排序 → 定张数 → 逐张成卡 → 格式自检」的流程直接
输出卡片，不输出寒暄或对请求的复述。生成后会先跑一遍内置校验脚本，修正所有 `FAIL` 再交付，
因此不需要人工核对格式。

## 输入输出示例

### 示例：中文科普文章（节选 2 张）

**输入**

```markdown
# 睡眠如何巩固记忆

记忆的形成大致分为编码、巩固与提取三个阶段。白天学到的信息最初以不稳定的形式暂存在
海马体，只有在睡眠中，海马体会把这些信息"重放"给大脑皮层，信息才会逐渐转移并稳定存储，
形成长期记忆。

睡眠由多个周期组成，每个周期约 90 分钟，包含非快速眼动睡眠（NREM）和快速眼动睡眠
（REM）。深度的慢波睡眠（NREM 第三阶段）对陈述性记忆的巩固最为重要；而 REM 睡眠则更多
与程序性记忆和情绪记忆的整合相关。

这解释了为什么熬夜复习往往事倍功半。睡眠不足还会影响注意力与工作记忆，使编码阶段的
效率下降。
```

**输出**

```markdown
## 知识卡片：睡眠是记忆巩固的关键环节

### 卡片 1：记忆形成的三个阶段
- **核心知识**：记忆的形成分为编码、巩固、提取三个阶段，作用各不相同。
- **简明解释**：编码在学习当下把外界信息转成神经信号；巩固让信息稳定下来；提取是日后
  回忆时调取信息。其中巩固决定信息能否长期留存。
- **自测问题**：记忆形成包含哪三个阶段？分别发生在什么时候？

### 卡片 2：睡眠通过海马体重放完成巩固
- **核心知识**：白天信息先暂存于海马体，睡眠中经"重放"转移到大脑皮层，才形成长期记忆。
- **简明解释**：编码后的信息最初并不稳定，只有在睡眠中由海马体把信息重放给皮层，信息
  才会转移并稳定存储，从而变成长期记忆。
- **自测问题**：为什么说睡眠是记忆巩固不可或缺的一环？
```

## 能力边界

暂不支持：

- 网页抓取（URL）
- PDF、Word、PPT、图片等二进制文档
- Anki 导出
- 图形界面

同时，单组卡片的硬上限是 12 张。源文极长时，Skill 会按源文自身的标题层级分节处理并把
重复项合并到同一组内；如需更细的颗粒度，可以按章节分别调用，每个来源产出独立的一组
卡片（用各自的 `## 知识卡片：` 标题分隔）。

遇到不支持的输入时，Skill 会明确说明限制，并建议改为粘贴文本或保存为 `.md` / `.txt`。

## 测试与验证

- **样例回归**：`references/examples.md` 中的 6 个完整样例同时是回归基线，改完规则后直接重跑：

  ```bash
  python skills/make-knowledge-cards/scripts/run_evals.py
  # RESULT: PASS | cases: 6 | failed: 0
  ```

- **单次校验**：产出草稿后（或人工编辑卡片后）单独校验一份卡片文件：

  ```bash
  python skills/make-knowledge-cards/scripts/check_cards.py cards.md
  # RESULT: PASS | cards: 6 | language: zh | fail: 0 | warn: 0
  ```

  脚本会拦截张数越界、缺少说明行、字段缺失或重复、核心知识含多个句子、标题为泛化词
  （`简介`/`其他`…）、标题重复或高度相似、正文与字段标签语言不一致等问题，退出码非 0
  即表示存在 `FAIL`。

- **结构校验**：使用 skill-creator 自带的校验脚本检查技能结构（`quick_validate.py` 位于
  skill-creator 技能包内）：

  ```bash
  python quick_validate.py skills/make-knowledge-cards
  # Skill is valid!
  ```

- 测试样例同时用来固化这些规则：例子优先取自原文、无例子时改用自测问题、并列规则是否拆卡、
  超过 8 张时的说明行、含代码时原样保留代码块。
